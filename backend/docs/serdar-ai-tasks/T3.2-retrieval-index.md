# T3.2 — Retrieval index

- **Story:** US3
- **Est.:** 5 ч
- **Зависит от:** T3.1 (FAQ base, Askhat), T0.7
- **Приоритет:** P2 — core
- **DoD (из спринта):** индекс строится из чистого состояния одной командой; ручная проверка 5 вопросов возвращает ожидаемый FAQ-пункт первым.
- **Статус: реализовано.** Индекс хранится в Postgres/pgvector (таблица `faq_embeddings`, 384 измерения). Код: [`app/assistant/retrieval.py`](../../app/assistant/retrieval.py), [`app/assistant/embeddings.py`](../../app/assistant/embeddings.py), миграции `0002` и `0005`. Тесты: [`tests/test_service.py`](../../tests/test_service.py).

## Что нужно сделать

Построить индекс поиска по FAQ-базе (эмбеддинги + keyword fallback) и скрипт reindex, который можно перезапускать при обновлении FAQ приёмной комиссией.

## План реализации

1. Дождаться выгрузки от T3.1 (Askhat): JSON/CSV с полями `question, answer, category, source_link, last_update`, ~30 записей, прошедшие ревью Serdar перед индексацией (это явно указано в DoD задачи T3.1).
2. **Embedding-индекс:** вектор по тексту «вопрос + ответ» FAQ-пункта считает локальная мультиязычная модель `paraphrase-multilingual-MiniLM-L12-v2` (fastembed, ONNX, 384 измерения) — без API-ключа и сетевых вызовов, одинаково локально, в CI и на деплое. Вопросы на русском и казахском находят английские FAQ-пункты.
3. **Keyword fallback не нужен:** модель работает внутри процесса, «провайдер недоступен» не бывает.
4. **Similarity scoring:** косинусная близость через `cosine_distance()` в pgvector.
5. **Reindex-скрипт:** `python scripts/reindex_faq.py` — полная пересборка таблицы (DELETE + INSERT). Контейнер API запускает его при каждом старте.
