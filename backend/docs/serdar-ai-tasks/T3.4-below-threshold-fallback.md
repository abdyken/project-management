# T3.4 — Below-threshold fallback

- **Story:** US3
- **Est.:** 2 ч
- **Зависит от:** T3.3
- **Приоритет:** P2 — core
- **DoD (из спринта):** вопросы вне базы FAQ всегда получают fallback-ответ; fail-кейс US3QATest (придуманная информация) не воспроизводится.
- **Статус: реализовано.** `build_fallback_response` — чистая функция без единого вызова LLM (guard от галлюцинаций гарантирован конструкцией кода, не промптом). Код: [`app/assistant/fallback.py`](../../app/assistant/fallback.py). Тест: [`tests/test_fallback.py`](../../tests/test_fallback.py).

## Что нужно сделать

Если similarity ниже порога — отвечать фиксированным сообщением "не удалось найти информацию, обратитесь в приёмную комиссию" + контакт офиса, и гарантировать, что генерация не может выдать информацию о приёме вне FAQ-базы.

## План реализации

1. **Фиксированное сообщение** + `ADMISSIONS_OFFICE_CONTACT` — значение согласовать с Askhat (тот же контакт приёмной комиссии, что используется в T0.6/T3.1).
2. **Guard от галлюцинаций:** below-threshold путь должен быть отдельной веткой кода, которая **не вызывает LLM для генерации фактов вообще** — только подставляет заранее заданный шаблон текста. Это полностью убирает риск придуманной информации для этого пути (дешевле и надёжнее, чем пытаться "сдерживать" LLM промптом).
   - Выше порога ответ — это `faq.answer` как есть, LLM не используется вообще. Fallback также срабатывает, если лучший FAQ-пункт написан для другой степени или другого типа абитуриента (поля `degrees`, `applicant_types` в `faq.json`).
3. **Тест-кейсы (для проверки DoD и как вход в T3.7):**
   - вопрос точно вне тематики (например, не про поступление) → fallback;
   - вопрос на грани порога → зафиксировать ожидаемое поведение и включить в accuracy-test-set (T3.7);
   - явная попытка спровоцировать выдумывание правил приёма → ответ не должен содержать ничего, кроме fallback-сообщения.

## Что нужно от других

- **Askhat** — актуальный контакт приёмной комиссии для сообщения fallback.

## Что отдаётся бэкенду/фронтенду

- Формат fallback-ответа — тот же response-контракт, что и обычный ответ (`answer`, `source_link` может быть пустым или ссылкой на общую страницу приёмной комиссии, `faq_id` — null, `similarity_score` — фактическое значение ниже порога), чтобы фронтенду (T2.5, Daniyar) не нужно было обрабатывать отдельный формат ответа.
