# T3.6 — Document question in the chat

- **Story:** US4
- **Est.:** 3 ч
- **Зависит от:** T3.3, T4.3 (Nurmek)
- **Приоритет:** P2 — core
- **DoD (из спринта):** ответ в чате возвращает тот же список документов, что и checklist-эндпоинт, для той же программы и типа абитуриента.
- **Статус: реализовано.** Код: [`app/assistant/intents.py`](../../app/assistant/intents.py) (распознавание), [`app/assistant/service.py`](../../app/assistant/service.py) — читает те же таблицы каталога и чек-листов, что и checklist-эндпоинт. Тесты — [`tests/test_service.py`](../../tests/test_service.py), включая missing-data warning (T4.3).

## Что нужно сделать

Обработать в ассистенте вопрос вида "какие документы нужны для программы <X>": распознать программу, вызвать checklist-эндпоинт (T4.3, Nurmek) и ответить в чате названием программы и списком документов.

## План реализации

1. **Распознавание интента:** для демо-масштаба (10-15 программ) — не полноценный NLU, а простое сопоставление по ключевым словам ("документы", "какие нужны", "required documents" и т.п.) + fuzzy-match названия программы из текста вопроса против списка активных программ.
2. **Резолвинг программы:** получить список программ через каталожный API (T1.3, Dinmukhamed) или отдельный внутренний запрос к БД программ (T1.1); сматчить упомянутую в вопросе программу.
   - Если программа не распознана однозначно (0 или >1 совпадений) → уточняющий/fallback-ответ в духе T3.4 ("уточните, пожалуйста, название программы"), не гадать.
3. **Вызов checklist-эндпоинта:** `GET /api/programs/{program_id}/checklist?applicant_type=...` — точный путь/параметры подтвердить с Nurmek (владелец T4.2/T4.3); applicant_type (local/international, bachelor/master) на этом этапе демо можно спрашивать явно в вопросе или брать дефолтным с уточнением в ответе, какой тип абитуриента предположен.
4. **Формирование ответа:** название программы + список документов (название, оригинал/копия, перевод, нотариальное заверение, дедлайн подачи) — как текст в поле `answer` контракта из T3.5, если расширенный формат не согласован отдельно.
5. **Missing-data warning (T4.3):** если checklist-эндпоинт вернул предупреждение "нет сохранённых требований для программы" — пробросить в чат то же предупреждение + контакт приёмной комиссии, а не пустой список.
6. **Проверка DoD:** для 2-3 тестовых программ сравнить построчно ответ чата с прямым вызовом checklist-эндпоинта — списки документов должны совпадать.
