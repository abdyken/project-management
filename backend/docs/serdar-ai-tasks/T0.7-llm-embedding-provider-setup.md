- **Story:** US3 (foundation block)
- **Est.:** 2 ч
- **Зависит от:** T0.1 (Stack and architecture decision)
- **Приоритет:** P0 — foundation
- **DoD (из спринта):** тестовый запрос с задеплоенного бэкенда возвращает ответ; ключ не лежит в репозитории; лимит расходов установлен.
- **Статус: реализовано** (offline/mock-режим протестирован; реальные ключи и лимит расходов — до деплоя). Код: [`app/config.py`](../../app/config.py), [`app/assistant/providers.py`](../../app/assistant/providers.py), смоук-тест — [`scripts/smoke_test_provider.py`](../../scripts/smoke_test_provider.py).
- **T0.1 подтверждён (Dimash, бэкенд):** Python 3.12 + FastAPI, SQLAlchemy + Alembic для миграций, PostgreSQL 16 + pgvector (эмбеддинги FAQ — в той же БД).

## Что нужно сделать

Выбрать провайдера для (1) генерации ответа и (2) эмбеддингов, получить API-ключ, положить в конфигурацию окружения, выставить лимит расходов и описать fallback на случай недоступности провайдера.

## План реализации

1. **Провайдер генерации:** Claude API (Anthropic) — для демо-объёма (30 FAQ, 10–15 программ) достаточно компактной модели (например, Haiku-класса) ради скорости и стоимости; более сильную модель можно включить позже через переменную окружения без изменения кода. Реализовано в `AnthropicLLMProvider` (raw `httpx`-клиент, без лишней SDK-зависимости).
2. **Провайдер эмбеддингов:** отдельный REST-клиент `RestEmbeddingProvider`, поддерживает OpenAI-совместимый формат (OpenAI или Voyage AI — выбор через `EMBEDDING_PROVIDER`). Дальше эмбеддинги пишутся в pgvector-колонку той же Postgres-БД (T0.1), см. T3.2.
3. **Mock-провайдеры по умолчанию** (`LLM_PROVIDER=mock`, `EMBEDDING_PROVIDER=mock`) — детерминированные, офлайн, без сети и ключей. Это позволяет разрабатывать и тестировать T3.2–T3.7 уже сейчас, до получения реальных ключей; переключение на прод — только через `.env`, без изменения кода.
4. Зарегистрировать ключи у обоих провайдеров, задать **spending/budget limit** в дашборде каждого провайдера (не полагаться только на код) — это ручной шаг, код уже готов принять ключи через `.env`.
5. `.env.example` (в репозитории, корень `backend/`) содержит плейсхолдеры:
   ```
   LLM_PROVIDER=mock
   LLM_API_KEY=
   LLM_MODEL=claude-haiku-4-5-20251001
   EMBEDDING_PROVIDER=mock
   EMBEDDING_API_KEY=
   EMBEDDING_MODEL=text-embedding-3-small
   LLM_SPENDING_LIMIT_USD=20
   ```
   Реальные значения — только в локальном `.env` (не коммитится) и в секретах CI/CD дев-окружения (T0.5, Nurmek).
6. Fallback-поведение на случай недоступности провайдера реализовано как `ProviderError` → эндпоинт ассистента (T3.3/router.py) возвращает 503, не зависая (см. ниже).
7. Smoke-test: `python scripts/smoke_test_provider.py` — бьёт напрямую в оба провайдера (или в mock, если ключи не заданы) и подтверждает, что они отвечают. Прогнан локально с mock-провайдерами — OK.

## Fallback при недоступности провайдера

- Таймаут или 5xx от LLM/embedding-провайдера → эндпоинт ассистента (T3.3) не должен зависать: внутренний таймаут ~4 c, затем ответ 503/504 с читаемым сообщением (см. контракт в T3.5).
- Это не подменяет below-threshold fallback (T3.4) — это отдельный случай "провайдер недоступен", а не "вопрос не найден в FAQ".
