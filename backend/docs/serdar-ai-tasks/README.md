## Что осталось не мной

Код покрыт тестами на реальной БД (`uv run pytest` в `backend/`). Что ещё осталось:

1. **T3.1 (Askhat)** — FAQ-база (`app/data/faq.json`, 35 пунктов с sdu.edu.kz) ждёт проверки приёмной комиссией.
2. **T0.5 (Nurmek)** — дев-окружение, на котором нужно официально прогнать `scripts/run_accuracy_test.py` с `ASSISTANT_BASE_URL` и выполнить US3QATest (приёмка требует деплоя, не локального прогона).
3. **T3.5** — фактическое подтверждение контракта от Daniyar (сам контракт и код готовы).

## Кто от кого зависит

**Serdar ждёт входные данные от других:**
- T0.1 (Nurmek) — решение по стеку/архитектуре и retrieval-подходу → блокирует T0.7.
- T3.1 (Askhat) — очищенная FAQ-база (~30 записей: question, answer, category, source_link, last_update) → блокирует T3.2.
- T1.1 / T1.3 (Dinmukhamed) — модель программы и поиск по каталогу → нужны для распознавания программы в T3.6.
- T4.2 / T4.3 (Nurmek) — checklist-эндпоинт и его контракт missing-data warning → блокирует T3.6.
- T0.3 (Dinmukhamed) — структура backend-проекта уже предполагает модуль `assistant` — туда встраивается код T3.2–T3.6.
- T0.5 (Nurmek) — дев-окружение, на котором прогоняются T3.7 и US3QATest.

**Serdar отдаёт другим:**
- T3.5 — контракт `/api/assistant/ask` для Daniyar → разблокирует T2.5.
- T3.6 — при готовности часть ответа в чате зависит от T4.3, но сама логика распознавания "какие документы нужны" — вклад Serdar в US4.

## Рекомендуемый порядок выполнения

1. **T0.7** — как только готов T0.1 (день 1).
2. **Черновик контракта T3.5** — сделать рано и отдать Daniyar ещё до полной реализации T3.3 (по sprint-заметкам T3.5 в критическом пути и блокирует T2.5, а сама задача занимает всего 1 ч — дешёво сделать contract-first).
3. **T3.2** — как только придёт FAQ-база T3.1.
4. **T3.3** → **T3.4** — сервис ответов + guard от галлюцинаций.
5. Подтвердить/зафиксировать T3.5 с Daniyar по факту реализации.
6. **T3.6** — как только у Nurmek готов T4.2/T4.3.
7. **T3.7** — прогон на дев-окружении (T0.5), финальная приёмка US3QATest.

## Definition of Done (сводно, из сплинт-документа)

- T0.7: тестовый запрос с задеплоенного бэкенда возвращает ответ; ключ не в репозитории; лимит расходов установлен.
- T3.2: индекс строится одной командой; ручная проверка 5 вопросов возвращает ожидаемый FAQ-пункт первым.
- T3.3: эндпоинт отвечает на типовые вопросы поступающих с совпадающим FAQ-пунктом и его ссылкой; порог настраиваемый.
- T3.4: вопросы вне базы всегда получают fallback; fail-кейс US3QATest (придуманная информация) не воспроизводится.
- T3.5: контракт записан в репозитории и подтверждён Daniyar.
- T3.6: ответ в чате возвращает тот же список документов, что и checklist-эндпоинт для той же программы и типа абитуриента.
- T3.7: задокументированы accuracy и список фейлов; все сценарии US3QATest прогнаны с записанным результатом.
